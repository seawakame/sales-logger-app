# 営業訪問ログ管理システム（PWA）

外回り営業がスマホから **1タップで現在地＋訪問内容を記録**し、管理者が **地図（Leaflet + OpenStreetMap）と一覧**で訪問履歴を確認できる Web アプリです。

- **有料 API キーは一切不要**（Google Maps API を使いません）
- 地図 : Leaflet 1.9.4（同梱）＋ OpenStreetMap タイル
- 住所 : OpenStreetMap Nominatim による逆ジオコーディング（GAS 側で実行）
- DB   : Google スプレッドシート / バックエンド : Google Apps Script
- PWA  : ホーム画面に追加してネイティブアプリのように起動・オフライン動作

---

## 1. ファイル構成

```
sales-logger-app/
├─ backend/
│   └─ backend.gs            GAS の全コード（API・逆ジオコーディング・初期セットアップ）
├─ public/                   ← このフォルダをそのまま静的ホスティングすれば動きます
│   ├─ index.html            画面（記録 / 一覧 / マップ / 設定 の4タブ）
│   ├─ manifest.json         PWA 定義（アイコン・起動方法）
│   ├─ sw.js                 ServiceWorker（オフライン対応・地図タイルのキャッシュ）
│   ├─ css/
│   │   └─ styles.css        スマホ最適化・ダークモード対応スタイル
│   ├─ js/
│   │   ├─ store.js          データ層（GAS通信 / ローカル保存 / 送信キュー / 住所変換）
│   │   └─ app.js            UI層（GPS取得・フォーム・一覧・地図・設定）
│   ├─ vendor/leaflet/       Leaflet 本体（CDN 不要・オフラインでも地図が動く）
│   └─ icons/                PWA アイコン（192 / 512 / maskable / apple-touch）
├─ tools/
│   ├─ serve.js              依存パッケージ不要のローカルサーバー
│   └─ make-icons.ps1        アイコン再生成スクリプト（色やデザインを変えたいとき）
└─ README.md
```

> **`backend/` は GitHub に公開していません。**
> `backend.gs` には Nominatim 用の連絡先メールを直接記載しているため、[.gitignore](.gitignore) で
> 除外しています。手元のフォルダと Apps Script 上には存在し、GitHub Pages で配信するのは
> `public/` の中身だけなので、除外しても運用に支障はありません。
> 連絡先をコードから外してバックエンドも公開したい場合は、`.gitignore` の `backend/` の行を
> 削除したうえで、メールをスクリプト プロパティ `CONTACT_EMAIL` に移してください。

### アーキテクチャ

```
[スマホ / PC ブラウザ（PWA）]
   │  GET  ?action=list      … 一覧・担当者マスタの取得
   │  POST {action:"create"} … 訪問ログの登録（Content-Type: text/plain）
   ▼
[Google Apps Script ウェブアプリ /exec]
   │        ├─→ Nominatim（無料・キー不要）で 緯度経度 → 住所 に変換
   ▼
[Google スプレッドシート]  Logs シート ＋ Members シート
```

> 通信できないときは端末内の**送信キュー**に退避し、オンライン復帰時に自動で再送します（同じ ID は二重登録されません）。

## 2. スプレッドシートのテーブル定義

### `Logs` シート（訪問ログ本体）— 1行目のヘッダー

| 列 | ヘッダー名（1行目） | 内容 | 例 |
|----|--------------------|------|-----|
| A | `id` | 一意ID（端末側で発行する UUID。再送時の二重登録防止に使用） | `9b5098ac-621a-…` |
| B | `created_at` | レコード作成日時（サーバー時刻） | `2026-08-18 14:04:18` |
| C | `updated_at` | 最終更新日時 | `2026-08-18 14:04:18` |
| D | `visited_at` | **訪問日時**（現在地を取得した瞬間の端末時刻。アプリからは変更不可） | `2026-08-18 14:04:00` |
| E | `member` | **担当者名**（Members シートからの入力規則付き） | `営業A` |
| F | `company` | **訪問先名** | `株式会社サンプル 本社` |
| G | `contact` | 先方担当者 | `購買部 山田様` |
| H | `category` | 訪問区分（新規訪問／商談／納品／アフターフォロー／不在・再訪／その他） | `商談` |
| I | `memo` | **訪問メモ** | `新製品を提案。次回見積提示。` |
| J | `lat` | 緯度 | `35.681236` |
| K | `lng` | 経度 | `139.767125` |
| L | `accuracy` | GPS 精度（メートル） | `8` |
| M | `address` | 逆ジオコーディングで自動取得した住所 | `〒100-0005 東京都千代田区丸の内一丁目` |
| N | `device` | 記録した端末情報（User-Agent） | `Mozilla/5.0 (iPhone; …)` |
| O | `deleted` | 論理削除フラグ。`TRUE` で一覧・地図から除外 | `FALSE` |

### `Members` シート（担当者マスタ）— 1行目のヘッダー

| 列 | ヘッダー名 | 内容 | 例 |
|----|-----------|------|-----|
| A | `name` | 担当者名（アプリのセレクトボックスに出る） | `営業A` |
| B | `color` | **地図ピンの色**（`#rrggbb`）。空欄なら自動で色を割り当て | `#e11d48` |
| C | `active` | チェックが外れている担当者は選択肢に出ない | `TRUE` |

> 両シートとも「営業ログ」メニューの **① 初期セットアップ** で自動生成されます。手作業で作る必要はありません。

## 3. ローカルで動かす（まずは 1 分で試す）

Node.js があれば、追加インストールは不要です。

```bash
node tools/serve.js
```

ブラウザで **http://localhost:5173** を開きます。

- **GAS の設定をしなくてもそのまま使えます**（＝ローカルモード。データは端末内 localStorage に保存）
- 「記録」タブ →「現在地を取得」→ 位置情報の許可 → 訪問先名を入れて保存
- **位置情報を取得しないと保存できません。**訪問日時は取得した瞬間の時刻で確定し、あとから変更できません
- 「一覧」「マップ」タブで確認できます

> **重要**：位置情報（GPS）と PWA は **`localhost` か `https://`** でしか動きません。
> スマホの実機で試すときは、後述の「フロントの公開」を行ってください（`http://192.168.x.x:5173` では GPS がブロックされます）。

Python 派の人は `cd public && python -m http.server 5173` でも構いません。

## 4. バックエンド（GAS）のセットアップ

### 手順 1. スプレッドシートを作る

1. [https://sheets.new](https://sheets.new) で新しいスプレッドシートを作成
2. 名前を「営業訪問ログ」などに変更

### 手順 2. スクリプトを貼り付ける

1. メニューの **拡張機能 → Apps Script** を開く
2. 既存の `function myFunction() {}` を**すべて削除**
3. `backend/backend.gs` の中身を**全部**貼り付ける
4. 保存（Ctrl + S）
5. **メールアドレスをコードに書く必要はありません。** Nominatim 用の連絡先は、貼り付け後に
   スプレッドシートのメニュー **営業ログ → ③ 連絡先メールを設定（任意・非公開）** から登録します。
   値はスクリプト プロパティに保存されるため、リポジトリを公開してもメールは公開されません。
   登録しない場合は `CONFIG.APP_URL`（既定 `https://example.com/sales-logger`）のみで
   識別子が構成され、これでも Nominatim の規約は満たします。公開後は自分のアプリ URL に
   書き換えておくと親切です。

### 手順 3. 初期セットアップを実行

1. スプレッドシートのタブに戻り、**リロード**（メニュー「営業ログ」が出ます）
2. **営業ログ → ① 初期セットアップ（シート作成）** をクリック
3. 初回は認証画面が出ます
   - 「権限を確認」→ 自分の Google アカウントを選択
   - 「このアプリは確認されていません」→ **詳細** → **「（プロジェクト名）に移動」** → **許可**
4. `Logs` シートと `Members` シートが自動生成されます
5. **営業ログ → ② API トークンを表示** で表示される 24 文字をコピー（後でアプリに貼ります）

### 手順 4. ウェブアプリとしてデプロイ

1. Apps Script 画面の右上 **デプロイ → 新しいデプロイ**
2. 歯車アイコン → **ウェブアプリ** を選択
3. 設定：

   | 項目 | 選ぶ値 |
   |------|--------|
   | 説明 | 営業訪問ログ v1 |
   | 次のユーザーとして実行 | **自分** |
   | アクセスできるユーザー | **全員** ← ここが重要 |

4. **デプロイ** → 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピー

> 「全員」にしても、スプレッドシートそのものが公開されるわけではありません。API トークンを知っている人だけが読み書きできます。

### 手順 5. アプリと接続する

1. アプリの **設定**タブを開く
2. **ウェブアプリ URL** に手順 4 の URL（末尾が `/exec`）を貼る
3. **API トークン** に手順 3 のトークンを貼る
4. **自分の担当者名** を選ぶと、記録画面で最初から選択された状態になります（`Members` シートの担当者から選ぶプルダウンです。初回接続前は初期値の `営業A`〜`営業D` が並ぶので、同期後に選び直してください）
5. **接続テスト** → 「接続 OK：（シート名）」と出れば成功
6. **保存** を押す（ローカルで記録済みのデータがあれば、アップロードするか聞かれます）

以降、記録はスプレッドシートに直接保存されます。

### コードを修正したときは

**デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**
（URL は変わりません。「新しいデプロイ」を選ぶと URL が変わってしまうので注意）

## 5. フロントを公開して PWA として設置する

GPS と PWA には **https** が必要です。`public/` フォルダを無料の静的ホスティングに置くのが最短です。

### 例 A. GitHub Pages（無料・おすすめ）

1. GitHub でリポジトリを作成し、`public/` の中身をプッシュ
2. リポジトリの **Settings → Pages** → Source を `main` / `/root`（または `/docs`）に設定
3. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

### 例 B. Netlify / Cloudflare Pages / Firebase Hosting

`public/` フォルダをドラッグ＆ドロップするだけ（ビルド不要）。

### スマホへのインストール手順

| 端末 | 手順 |
|------|------|
| **Android（Chrome）** | 公開 URL を開く → 右上 **⋮** → **アプリをインストール**（またはアプリ内「設定」タブの **📲 ホーム画面に追加**） |
| **iPhone（Safari）** | 公開 URL を開く → 下部の **共有ボタン**（□↑）→ **ホーム画面に追加** → 追加 |

ホーム画面のアイコンから起動すると、アドレスバーのない全画面アプリとして動作します。

### 初回だけ各担当者の端末でやること

1. アプリを開く →「設定」タブ
2. **ウェブアプリ URL** と **API トークン** を入力（社内チャットで配布してください）
3. **自分の担当者名** を選んで **保存**

> URL とトークンをあらかじめ埋め込んでおきたい場合は、`public/js/store.js` の
> `{ apiUrl: '', token: '', myMember: '' }` に初期値を書いておけば、担当者側の入力は不要になります。

### オフラインでの挙動

- アプリ本体・Leaflet・**一度表示した地図タイル**はキャッシュされ、圏外でも起動・閲覧できます
- 圏外で記録すると「未送信」として端末に保存され、ヘッダーに `未送信 n 件` と表示されます
- 電波が戻ると自動送信されます（手動なら「設定 → 今すぐ同期」）

## 6. 運用のヒント

### 担当者を追加する / ピンの色を変える

`Members` シートに行を足すだけです（アプリ側は次回同期時に反映）。

| name | color | active |
|------|-------|--------|
| 鈴木 | `#0d9488` | ✅ |

`color` を空欄にすると、10 色のパレットから自動で割り当てられます。
退職・異動した担当者は `active` のチェックを外すと選択肢から消えます（過去ログはそのまま残ります）。

### 住所が空のログをまとめて補完する

通信状況によって住所が取得できなかった場合、**営業ログ → 住所が空のログを一括補完**を実行してください。
自動化するなら Apps Script の **トリガー → 時間主導型 → 1時間おき** に `fillMissingAddresses` を登録します。

### 集計・分析

スプレッドシート側は普通の表なので、そのままピボットテーブルや `QUERY` 関数で集計できます。

```
=QUERY(Logs!A:O, "select E, count(A) where O = FALSE group by E label count(A) '訪問件数'", 1)
```

アプリの「一覧 → ⬇ CSV」でも、絞り込んだ結果を Excel 用（BOM 付き UTF-8）で出力できます。

### API 仕様（他システムから叩く場合）

| メソッド | 内容 |
|----------|------|
| `GET  ?action=ping` | 疎通確認（認証不要） |
| `GET  ?action=list&token=…&member=営業A&limit=500` | 一覧取得 |
| `GET  ?action=members&token=…` | 担当者マスタ |
| `GET  ?action=geocode&token=…&lat=…&lng=…` | 逆ジオコーディング |
| `POST {action:"create", token, record:{…}}` | 登録（`id` を指定すれば冪等） |
| `POST {action:"update", token, record:{id, …}}` | 更新 |
| `POST {action:"delete", token, id}` | 論理削除（`hard:true` で行削除） |

> POST の `Content-Type` は必ず **`text/plain;charset=utf-8`** にしてください。
> `application/json` にすると CORS プリフライトが発生し、GAS 側で必ず失敗します。

## 7. トラブルシューティング

| 症状 | 原因と対処 |
|------|-----------|
| 「現在地を取得」でエラーになる | `http://192.168.x.x` など **https でも localhost でもない** URL で開いている。https で公開するか PC の `localhost` で確認してください |
| 位置情報が「許可されていません」 | ブラウザのアドレスバーの鍵アイコン → 位置情報を「許可」。iPhone は 設定 → プライバシー → 位置情報サービス → Safari も確認 |
| 接続テストで「Failed to fetch」 | ①URL の末尾が `/exec` か（`/dev` は不可） ②デプロイの「アクセスできるユーザー」が **全員** か ③コード修正後に「デプロイを管理 → 新バージョン」をしたか |
| 「認証エラー: トークンが一致しません」 | 「② API トークンを表示」の値と設定画面の値が違う。コピー時の空白に注意 |
| 保存はできるが住所が空になる | Nominatim が一時的に応答していない可能性。**住所が空のログを一括補完**で後から埋められます |
| 地図が真っ白 | オフラインで未キャッシュのエリアを表示している。オンラインで一度開くとキャッシュされます |
| 修正したのに画面が変わらない | ServiceWorker のキャッシュ。「設定 → 更新を確認」を押すか、スーパーリロード（Ctrl + Shift + R） |
| ピンの色が全員同じ | `Members` シートの `color` 列が同じ値になっている。`#rrggbb` 形式で別々の色を入れてください |

## 8. 制約・注意事項

- **Nominatim（無料）の利用制限**：1 秒あたり 1 リクエストまで。GAS 側でスロットルと 6 時間キャッシュを実装済みですが、**大量の一括処理は避けてください**。商用で高頻度に使う場合は自前の Nominatim を立てるか有料ジオコーダーを検討してください。
- **OpenStreetMap タイル**：個人・小規模利用の範囲で無料です。全社規模で常時使う場合はタイルプロバイダの利用規約を確認してください（`app.js` の `osmLayer()` を差し替えれば他のタイルにも変更できます）。
- **GAS の実行制限**：1日あたりの実行時間・UrlFetch 回数に上限があります（無償アカウントで UrlFetch 2万回/日）。通常の営業利用では十分です。
- **同時書き込み**：`LockService` で排他制御しているため、複数人が同時に保存しても行は壊れません。
- **セキュリティ**：API トークンはクライアントに保存されるため、機密性の高い情報の保存には向きません。社内限定運用や、必要に応じてアクセスを Google アカウント認証（デプロイ設定を「自分のみ」等）に変更してください。

## 9. 動作確認済みの内容

- GAS バックエンドのロジック（初期セットアップ／認証／登録の冪等性／一覧・絞り込み／更新／論理削除／逆ジオコーディング整形）
- 逆ジオコーディングの住所整形（東京 23 区・大阪市・札幌市・政令市の区など実データで検証）
- フロント：GPS 取得 → 地図表示 → 保存 → 一覧 → ピン色分け → ポップアップ → 絞り込み → CSV 出力
- オフライン記録 → 送信キュー退避 → オンライン復帰で自動再送
- ServiceWorker によるアプリ本体および地図タイルのキャッシュ
